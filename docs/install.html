AICO WIKI / 首次使用

安装插件即可建库，已有资料按需导入

知识管理统一使用 AICO Wiki，主 Skill 为 aico-wiki。新库不需要下载预置知识仓，也不要求先准备四个 JSON 注册表。插件提供知识页、会话绑定、关系图和历史沉淀审阅。

  1. 先安装本次 beta0.1 的 Harness，再安装 Wiki 插件。
  2. 打开 AICO Wiki，创建空知识库并新建整理会话，或绑定已有会话。
  3. 需要原论文、仓库分析和网页资料时，单独下载旧 AICO 知识库，再通过“导入资料”预览并审阅。

知识资料独立于插件保存。新用户直接创建空库；原用户保留旧资料目录，在 Wiki 中按需导入。当前没有单独发布的官方知识资料下载包。

从旧 Knowledge 迁移

旧插件已停止新安装和发布。保留原资料及 catalog.json，在 Wiki 的旧目录导入中预览并审阅；Markdown/TXT 导入不等于全部 PDF、图表和公式资产已迁移。

已安装旧插件的用户，可在对应 Profile 的 DSH Terminal 执行 dsh plugin remove aico-knowledge。卸载插件不需要删除知识资料、历史会话或 Wiki 的 SOUL。

导入范围与旧数据保留

首版只读导入 Markdown / TXT，分批冻结为待审阅候选；原目录不修改。PDF、图像、公式资产及自动采集的完整迁移仍在适配。插件包与知识内容分别更新，卸载不删除业务数据。

04

开始工作

配置模型连接

Windows 工作区

业务、Agent 和工具始终在 Windows。登录和选择连接环境在“AICO 信息 → 模型网关”；提供方与模型继续在原装“模型”页配置。安装并重启后，在“AICO 信息 → 插件信息”核对版本。使用本机模型无需配置 WSL；登录成功后还需进行实际模型请求验证。

默认

本机连接

使用当前 Windows 环境的模型设置和凭据。

可选

通过 WSL 连接模型

当需要通过 WSL 接入模型时，可以选择配置。默认 Linux 用户为 root，可在 Host 配置指定其他用户。各环境凭据独立保存。当前指定环境已验证；发行版扫描、独立依赖准备与修复尚未形成通用交付。

安装说明

操作中的几个边界。

下面是安装时容易混淆的地方；开发与发布细节集中在开发者页。

怎样执行插件安装命令？

从原版 Desktop 托盘打开 DSH Terminal，在当前 Profile 中运行 dsh plugin add "<下载包的完整路径>" --ignore-scripts。占位文字需换成真实下载路径；安装结束后保存工作并重启 Desktop。

WSL 需要安装另一套 Desktop 或业务插件吗？

不需要。WSL 只是 Windows 版 Harness 的可选模型通信方式，不是第三个插件平台。PPT、Profile、Wiki 和工具只在 Windows 运行。

WSL 模型网关如何工作，需要准备什么？

Windows 中的 Harness 通过 wsl.exe 启动所选 Linux 用户下的模型网关，使用进程输入输出管道传递模型请求和流式响应，不开放局域网监听端口。当前 WSL 链路用于 openai-codex；模型返回的工具调用仍由 Windows Agent 执行，结果再送回模型。

这是可选功能：使用本机连接无需安装 WSL。启用前需准备可运行的 WSL Linux 发行版、所选用户的 Bash 和 Linux Node.js，以及该用户可访问模型服务的网络环境；需要代理时，在该 Linux 用户环境配置。登录授权与令牌刷新也在该环境完成。

Harness 包含网关程序；网关还需要匹配版本的原装模型、授权、凭据和代理运行依赖，不需要安装完整 Linux DSH、另一套 Desktop、PPT、Profile、Wiki 或 Linux 业务运行时。当前依赖交付及可复现的安装命令仍待验证，正式说明会补充经验证的 Node.js 版本和依赖来源。

发行版、Linux 用户、Node.js 路径和依赖路径目前通过 Host 插件配置指定；开发默认值为 Ubuntu-26.04/root，不代表所有用户必须使用这个组合。官网将提供手动准备步骤，自动扫描与一键准备不是使用该功能的前提。

授权会从 Windows 自动带到 WSL 吗？

不会。Windows 与每个 WSL 发行版/用户的模型凭据分别保存；在哪个环境登录，只在该环境生效。迁移旧版时也不复制或借用其他环境的凭据。

离线安装与旧版迁移现在可用吗？

通用离线交付和旧版数据迁移仍需单独验收。旧版 Windows 附件仅用于维护原有环境，见 历史发行记录；不要将它导入 AICO 2.0。
