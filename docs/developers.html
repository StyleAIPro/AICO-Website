beta0.1 · 四仓库源码标签与 Windows 安装包已发布
准备环境获取源码构建与安装业务插件验证与发布

01 / 环境

先准备原版宿主。

Windows x64，原版 DSH Desktop 2.0.13（配套 DSH 0.1.5-rc.2）。开发 Node 版本应满足 Harness 与 Wiki 声明的 ^22.19.0 || ≥24，按锁文件安装依赖。

获取原版 Desktop ↗

宿主源码仅用于接口阅读与原版验证。AICO 通过原版插件机制接入，不需要修改或构建 AICO 版 Desktop。

02 / 源码

按需要获取代码仓。

git clone https://gitcode.com/AICO-Ascend/AICO-Harness-Plugin.git
cd AICO-Harness-Plugin

本次源码统一使用 beta0.1 标签。各插件保留独立包内版本；请按下表固定提交，不以默认分支替代发布标签。

仓库职责依赖与状态
AICO-Harness-Plugin ↗适配与模型网关原装 Desktop / DSH
AICO-PPT ↗演示创作与编辑Harness + Windows 资源
AICO-Profile ↗性能分析与专业视图Harness + Insight 运行时
AICO Wiki ↗知识库与会话沉淀Harness + Windows 知识库插件
AICO-Website ↗官网与发布索引GitHub Pages

03 / 适配插件

构建，然后交给原装终端安装。

在 Harness 仓库根目录执行：

npm ci --ignore-scripts
npm run build
npm test
npm pack --ignore-scripts

构建生成客户端，打包命令输出本次实际 .tgz 文件名。从 Desktop 托盘打开 DSH Terminal，使用该文件的完整路径：

dsh plugin add "<本次生成的插件包完整路径>" --ignore-scripts

安装完成后保存工作并重启 Desktop，在“设置 → AICO 信息 → 插件信息”核对登记版本。

04 / 业务插件

只构建你要开发的能力。

以下命令分别在对应仓库根目录执行。打包成功不等于资源和系统验收完成。

PPT · 本地开发
npm ci --ignore-scripts
npm run test:dsh-plugin
npm pack --ignore-scripts

编辑器与导出依赖还需按仓库 INSTALL.md 准备；不要把插件包当作完整运行环境。

Profile · 本地开发
npm ci --ignore-scripts
npm test
npm pack --ignore-scripts

专业视图还需要匹配的 Insight / 原生运行时。准备与构建分别参考 prepare:runtime、build:native 脚本及仓库说明。

Wiki · 本地开发
npm ci --ignore-scripts
npm test
npm run dev

在当前本地 AICO-wiki 目录开发。npm run dev 用于独立工作台预览，不能代替原装 Desktop 验收；插件打包使用 npm pack --ignore-scripts。

业务包同样通过 DSH Terminal 安装。Wiki 可从空知识库开始；旧 Knowledge 插件需要另备完整知识资料。两者的数据准备流程不同。

05 / 验证

从能构建，到能交付。

  • 在原版 Desktop 验证安装、卸载、业务流程与原装插件共存。
  • Windows 执行工具；如使用 WSL，只切换模型通信，分别验证流式响应、取消和工具回传。
  • 图片工具结果已具备跨网关链路；普通文件转换与任意路径读取需分别核对，网关不提供通用文件读取。
  • 锁定仓库 commit、依赖和资源摘要，使用最终包验收后再发布。

beta0.1 的四个源码标签和四个 Windows 单包附件已发布，附件均已匿名重新下载并校验 SHA-256。本次提供手动安装；该 Beta 清单不替代正式签名版本索引。最终业务联合验收和 WSL 独立依赖交付仍待完成。
